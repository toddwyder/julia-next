# Verify machine

Generated by the project-local `create-verification-skill` workflow from the repository-and-laptop
interview recorded in `generation.json`. This is a control skill for the machine as it works today,
not a promise that every exposed command is healthy. Read `features/README.md` before choosing a
drive. Never recreate Mastra Factory or alter a permanent machine part.

## Launch

There is no server or shared session to launch. Use the checked-out candidate from the repository
root. The surface is a set of short-lived Node and Windows PowerShell commands. If either lockfile's
installed tree is stale, run its matching `npm ci` before verification.

Create one run-owned evidence directory:

```powershell
$runId = "$(Get-Date -Format 'yyyyMMddTHHmmssfff')-$PID"
$evidenceDirectory = Join-Path '.artifacts/verify-machine' $runId
New-Item -ItemType Directory -Path $evidenceDirectory | Out-Null
```

A drive is ready when its process starts from the repository root with no unidentified delivery
owning the real Julia configuration. The mapped drives start no persistent process, so their exit is
their teardown. Commands that require a Julia vault secret must run through
`scripts/julia-vault-windows.ps1`; never supply personal 1Password authentication.

## Doctor

Run Doctor before every feature drive. It is read-only and answers whether the checkout identity and
all recorded permanent prerequisites are worth driving:

```powershell
$doctorPath = Join-Path $evidenceDirectory 'doctor.json'
$doctorOutput = node --experimental-strip-types ops/mastra-agents/reviewer/src/mastra/verify-machine.ts doctor 2>&1
$doctorExit = $LASTEXITCODE
$doctorOutput | Set-Content -Encoding utf8 $doctorPath
if ($doctorExit -ne 0) { throw "verify-machine Doctor failed with exit code $doctorExit" }
$doctor = Get-Content -Raw -LiteralPath $doctorPath | ConvertFrom-Json
if (-not $doctor.ok) { throw 'verify-machine Doctor reported an unhealthy candidate' }
```

Require the reported commit and dirty-tree digest to match the candidate being proved. Doctor checks
the permanent-parts inventory read-only; never edit the inventory or manufacture a missing part.

## Drive

Read `features/README.md`, select exactly one mapped working feature, and follow that file's literal
PowerShell recipe. The real drivers currently mapped are:

- `verify-machine doctor` for installed prerequisite health;
- `julia-vault-windows.ps1 -Verify` for restricted secret resolution; and
- `julia-vault-windows.ps1 -RunArguments` for an approved command using explicitly named secrets.

Do not drive `connections`, `models`, or `init` as if they work on today's laptop. The index records
their observed unavailable state and the retained `rehearsal` helper's status. Tests guard the
recipes but never substitute for the selected real drive.

## Evidence

Keep evidence under `$evidenceDirectory`. Retain `doctor.json` plus a drive record containing the
feature ID, exact command, expected result, stdout, stderr, exit code, timestamps, and side effects.
For persisted behavior, retain a second user-facing readback. A proof uses the real command and real
boundary; do not substitute a fixture, mock, internal setter, test-only endpoint, or unidentified
existing process.

Before handoff, require all evidence files to remain readable and confirm that Doctor's
`candidateCommit` and `dirtyTreeDigest` identify the exact candidate. Never include secret values,
bootstrap material, or personal authentication in evidence.

## Cleanup

Stop only processes whose PIDs this run captured. Never kill by process name. The three mapped
features are short-lived and create no persistent process or scratch configuration. If a failed
attempt created a run-owned scratch directory, resolve its absolute path, prove it is below
`$evidenceDirectory`, then remove only that directory.

Do not remove evidence, real Julia configuration, sign-ins, package installs, the permanent-parts
inventory, or any permanent prerequisite. Confirm cleanup without consuming the proof:

```powershell
if (-not (Test-Path -LiteralPath $evidenceDirectory)) { throw 'verification evidence was removed' }
Get-Content -LiteralPath (Join-Path $evidenceDirectory 'doctor.json') -TotalCount 20
Get-ChildItem -LiteralPath $evidenceDirectory -File | Select-Object Name, Length
```

## Helpers

`ops/mastra-agents/reviewer/src/mastra/verify-machine.ts` is the executable Doctor helper. Its
`rehearsal EVIDENCE_PATH` command remains for compatibility, but it is an aggregate paid diagnostic,
not a mapped current feature; do not run it unless a card explicitly requires every live route and
the accepted limits cover it.

`scripts/julia-vault-windows.ps1` is the only Windows launcher for Julia vault secrets. `-Verify`
checks the provisioned restricted account without displaying values. Pair `-SecretNames` with
`-RunArguments` to expose only named fields to an approved executable. `-Provision` is an account
action and is not routine verification.

The structural guard is `node --test --test-reporter=spec scripts/verify-machine-skill.test.mjs`.
The focused compatibility suite is
`npm --prefix ops/mastra-agents/reviewer run test:jul-225`, and the complete machine gate is
`node scripts/julia-runner-suite.mjs`.
