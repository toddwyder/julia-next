# 0018 The running card, the runner and the per-card limit

Todd, 27 Oct 2026. The running card expands in place on the board: no back arrow and no header, the same title row opens and folds it. The runner that starts, watches and stops builds is a Mastra workflow, and it also monitors each agent and records its context fill and compactions. The dashboard's own Start is built first, so hand-run cards are not shown and no screen needs a separate status for them; the walkthrough statuses are Exists, Build must make it work, Open question, and Drawn by Stitch, not built. The per-card limit asks Todd instead of stopping anything: past the limit the card gets an amber mark, Todd gets a notification and a Needs you item (keep going or stop), and the build keeps running until he answers, so money still never stops a card by itself. That is a seventh kind of Needs you item next to the six in picture 06. The limit's value is set later from real cards (about the 75th percentile, plus a check for repeating without progress); until then there is no limit. Rejected: a limit that only changes how the cost is written (it does nothing), and a limit that stops the card (against "money never stops a card").
