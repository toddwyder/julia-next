### Standing stop policy

On any blocker other than (a) an account action, (b) money beyond the authorized limit, or
(c) a product decision, make the smallest reversible repository fix and continue. Record that
choice in the final report. Do not use a reversible repository defect as a reason to stop or ask
Todd for a workaround.

Work to the brief's finish line. A completed step is not a stopping point. Waiting on CI or any background job is not a stop: wait for it and continue.

A single failed review or failed Proof is round 1: diagnose from evidence, fix test-first and continue. The root-cause report and restart plan below apply only when a card stops for exactly one of these reasons: two rounds without closing, a spend cap, or a time cap.

An evidenced fault in a test or Proof driver is repaired test-first and rerun; it does not count as a failed review or Proof round when the product behavior it attempted to check remains unproved. Retain the failed evidence and identify the fault before replacing the check.

Whenever a card stops for any reason: two rounds without closing, a spend cap or a time cap, the agent writes a root-cause report that proposes no fix, then a restart plan, and nothing is rebuilt until Todd approves the restart plan. Every restart plan and brief must state what happens to code already built for the card that doesn’t meet its acceptance criteria:

- It is removed from the repo and from the machines it was installed or configured on. Delete exactly that piece and everything belonging to it; the reviewer confirms a search finds no trace.
- It is never worked around.
- Undoing (a revert, or restarting from main and carrying over only what meets the criteria) is offered before patching.

### Preflight

Before any task, verify the applicable entry points, the launcher's accepted command list,
configuration and authorized spend limits, required credentials, and branch/worktree state. Fix
what is safely fixable before starting work. Confirm each tool the card uses is at the version its brief or lockfile names, and that its automatic updates are off. Spend limits belong in
accepted ADRs and dated card decisions, never in prompts. The reviewer limit is **$1.00 per card**.
[Permanent machine parts](docs/agents/permanent-machine-parts.json) are preflight prerequisites and no cleanup ever removes them.
On Windows, every local command that needs a Julia vault secret must run through
`scripts/julia-vault-windows.ps1`; its default configuration is the provisioned restricted Julia
service account. Never use personal 1Password desktop authentication for those commands. Direct
`julia-vault.mjs` key operations fail closed when the service-account bootstrap is absent.

Publishing is part of the card's finish line, so work to it without stopping. When review and Proof pass: push the exact reviewed candidate to a branch, open or resume one pull request, and wait for CI on that exact commit. A machine card then merges without asking Todd, and the agent confirms main contains the merged commit. A Julia product card stops for Todd's household test of the preview and merges only the commit he tested. After merging, post the result and links on the card and delete every branch and file you created that the card's brief doesn't name. Use ordinary signed-in GitHub access. Never ask Todd to run any of these steps or to relay a message between agents.
