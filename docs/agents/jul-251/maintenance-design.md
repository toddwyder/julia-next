# Merge-triggered verification maintenance

A merge observation contains the repository, watched branch, merge SHA, parents, and associated merged PRs. Durable run state is claimed, running, clean, changed, or blocked. Repository and branch configuration own the state directory; the merge SHA owns one run within it. The first poll records a baseline without replaying old history.

The server's user systemd timer polls an independent bare clone. New first-parent commits with multiple parents qualify. Exact GitHub associated-PR readback qualifies squash or rebase merge tips too. A direct push does not. A claim is durable before one fresh Codex coordinator starts. Repeated polls do not relaunch a claim. Interrupted claims become blocked reports with retained session evidence.

A target is a project `.agents/skills/verify-*` directory containing both `SKILL.md` and `features/README.md`. The coordinator reads and runs the existing maintenance skill for every discovered target. Signed-in ChatGPT plan authentication and the user's configured model are retained. API credentials are removed from the worker environment, and its provider is the ordinary OpenAI signed-in route. No model selection, provider billing call, or package updater belongs to observation.

An exact-merge checkout is read-only inside Bubblewrap. Writable mounts cover only target skill folders, scratch evidence, Codex session storage, installed dependencies, and disposable runtime output. A real mount proof rejects product and sibling-skill writes while allowing target-skill writes. The controller also requires unchanged HEAD and checks every proposed source path against the discovered targets. The worker cannot commit because Git metadata is read-only. The controller alone publishes.

Clean produces no branch or PR. Changed requires a nonempty scoped correction and retained live evidence, then creates one corrections PR with ordinary signed-in GitHub access. Blocked produces no PR and automatically posts one line on JUL-251 through the existing stable server vault wrapper and Linear CLI. It retains that line in the run's `TODD.txt`. The controller retries pending delivery on later polls and reads back the full-SHA comment marker before posting, which recovers a successful delivery whose response was lost. Notification identity and errors remain in the durable run record. The server retains every session's JSONL, structured result, source checkout, scratch proof, and notification. A product regression is reported without changing product source.

The rerunnable proof uses the same production observer, launcher, sandbox, schema, and unmodified maintenance skill. A real local throwaway branch stands in for main. Its one-feature CLI fixture makes the live pass finite and auditable. The proof covers no-merge and direct-commit zero launches, one true merge and exactly one actual fresh signed-in session, duplicate polling with zero additional launches, and filesystem edit scope. It does not claim to have run Julia's complete maintenance pass or merged PR #314.

Model the Domain made lifecycle state and merge identity explicit. Make Operations Idempotent made the durable SHA claim the deduplication boundary. Test Behavior, Not Implementation made tests observe real Git history and filesystem writes. Prove It Works required a real Codex session and live CLI output in the replay evidence.
