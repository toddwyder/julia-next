# CI ownership grounding.

The first PR #314 Windows failure is reproduced by source. `.github/workflows/ci.yml` installed only root and `ops/mastra-agents/reviewer` dependencies, then invoked `scripts/julia-runner-suite.mjs`. That script walks the repository and runs every unknown `.test.mjs` unless its exact path is in `NON_RUNNER_TESTS`. New framework `credentials.test.mjs` and `usage-request.test.mjs` escaped that list and imported `framework-runtime.mjs`, whose explicit dependency owner is `ops/build-runner/package.json`. New `ops/build-runner/test/review-regressions.test.mjs` likewise ran without its SDK installation. The saved failed log records module-not-found for both routes. The same catch-all collected `scripts/verify-machine-skill.test.mjs`, whose own skill no longer contains `generation.json`. Its test survived its owner. `scripts/julia-runner-suite.test.mjs` enshrines the catch-all and the Windows gate through text assertions. `scripts/ci-routing.mjs` adds another hand-kept path routing layer.

Installed documentation read on this server was `npm help folders` from npm 11.11.0. It says local dependencies go under the current package root's `node_modules`, matching Node package-relative resolution. `node --help` from Node v24.14.1 documents `--test` and `--test-concurrency`. CI currently pins Node 22.23.2. No new provider/tool configuration is proposed. Existing framework declarations and runtime require the SDK pinned at 1.14.0 in `ops/build-runner/package-lock.json`.

The domain is a test owner `{ directory, package.json, package-lock.json, environment, tests }`. A test's nearest package-and-lockfile ancestor owns it. Environment follows an ancestor directory named `server`. Source data and tracked source boundaries, rather than arrays of test names, decide discovery. Skills are ownership boundaries for lifetime only. Skill tests stay inside their skill, then inherit the enclosing dependency owner.

## Sketch A. Move tests to dependency owners, discover nearest locked package.

Move the external SDK framework directory under `ops/build-runner/framework/@mastra/code-sdk`, preserving relative helper relationships and correcting only root-relative references. Move `scripts/julia-agents.test.mjs` under `scripts/server` and live provider framework tests under the build-runner's `server` subtree. Tests that import those server helpers stay under the same subtree. Discovery walks Git-tracked source files, groups each `.test.mjs` or `.test.ts` by nearest directory containing both package.json and package-lock.json, and assigns its environment from a `server` path segment. It skips generated artifacts by using Git source identity, not folder-name allowlists. CI installs every discovered package, then executes its discovered ordinary tests. Server tests execute on this server through the already provisioned key wrapper. Delete the orphan machine skill test and remove the Windows-specific routing suite and obsolete routing tests with their code. Keep the stable `checks` gate.

This is recommended. New local tests inherit package ownership without a metadata edit. New live tests enter `server` and inherit their server execution environment. Moving an owning skill deletes its tests naturally. The proof can invoke the discovery command on the actual new paths and run the exact adapter regression with the build-runner SDK installed. It can also assert the old verify-machine path is absent from tracked sources and the execution plan.

## Sketch B. Package workspaces and package-local npm test.

Convert the repository into npm workspaces, give framework tests their own package referencing the build-runner SDK, and split server packages into a `server` workspace tree. Use `npm ci` at root and `npm run test --workspaces --if-present`. Each owner defines a `test` command for its subtree; skills stay beneath owners. CI and server execute workspace packages by structural placement.

This provides standard npm execution but adds workspace lockfile migration, a second framework dependency declaration, and per-package test scripts. The root npm test command still needs care to avoid recursively collecting nested workspace tests. It is a larger change with no benefit for the stated failure. Prefer A.

The applied principle is Encode Lessons in Structure. It removes the inclusion/exclusion instruction instead of growing it. Fix Root Causes changes ownership before installing a missing package into the wrong runner. Model the Domain represents package ownership directly. Test Behavior, Not Implementation replaces text assertions about Windows YAML with executable fixture tests proving automatic ownership, actual execution, server routing, and exclusion through owner removal.
