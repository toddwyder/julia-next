## Candidates, ordered by severity

### 1. Make the concurrency proof deterministic — still open

The subprocess test starts two reservations with `Promise.all` and checks that exactly one succeeds. That demonstrates the observed result, but the processes can execute serially. The mutation report explicitly excludes removal of transaction locking because there is no deterministic barrier. The 43 caught mutations therefore do not prove that this central concurrency guard is necessary.

Improve the existing ledger test harness so two processes are forced to contend at the accounting boundary. Require removal of transaction protection alone to produce the forbidden observable result, then restore it and show one accepted reservation and one refusal. Keep this in the existing mutation proof, with a named gap until demonstrated. This strengthens proof of the card's existing concurrency requirement; it adds no spending permission or delivery restriction. It is not evidence that the current ledger is broken.

### 2. Let package ownership determine the execution environment — repaired; retain the structure

The first PR run failed because the Windows runner lacked the new SDK installation and still ran a test for the deleted verify-machine skill. Local green results had not exercised that environment. The follow-up then exposed a second environmental dependency: a Node test launched Chromium, but CI installed browsers only for browser-spec owners. Another AGENTS.md reminder or a second test registry would duplicate working machinery.
