# JUL-231 retrospective

JUL-231 ultimately passed, but the environment made the run substantially longer and less reliable
than necessary. The implementation session lasted 5.66 hours after takeover and required more than
twenty proof-driven repair commits before merge. The candidates below improve the coding-agent
environment rather than revisiting the accepted product decision.

## 1. High: run the TypeScript machine tests and typecheck in CI

The Windows CI gate runs `scripts/julia-runner-suite.mjs`, whose discovery includes only
`.test.mjs` files. It therefore omits the machine behavior suites in
`ops/mastra-agents/reviewer/test/*.test.ts`, including JUL-231's fourteen focused tests. The
existing reviewer `typecheck` command is also not invoked by CI.

Add one package script that runs all deterministic machine `.test.ts` suites with Node's TypeScript
stripping enabled and then runs `tsc --noEmit`. Invoke that script from the `julia-init-windows` CI
job. JUL-231's decisive focused checks currently pass only when an agent remembers to run them
manually.

Relevant files:

- `.github/workflows/ci.yml`
- `scripts/julia-runner-suite.mjs`
- `ops/mastra-agents/reviewer/package.json`
- `ops/mastra-agents/reviewer/test/jul-231.test.ts`

## 2. High: replace the Build-proof PowerShell wrapper

The `build-ready-run` recipe starts the Node driver with `Start-Process -Wait` while redirecting both
output streams. That wrapper deadlocked after the Node driver had successfully exited in two
separate proof runs. The verifier had to interrupt the wrapper and reconstruct
`build-command.json` from the driver's completed `drive.json`.

Replace the wrapper with a small tested launcher that directly owns the child process, captures
stdout, stderr and exit code, writes the command record atomically, and terminates naturally. A
successful machine proof should never require manual interpretation of a hung parent process.

Relevant file:

- `.agents/skills/verify-machine/features/build-ready-run.md`

## 3. High: enforce the controller-size rule mechanically

`ops/mastra-agents/reviewer/src/mastra/build-phase.ts` reached 486 lines. The independent reviewer
noticed the violation but classified it as non-blocking. The existing framework lint defaults to
`graph/langgraph`, so it cannot detect oversized Mastra controllers and is not run by the reviewer
Windows gate.

Extend the deterministic `max-lines` check to every controller directory governed by
`CODING_STANDARDS.md`, and run it from the applicable CI gate. This is a fixed syntactic condition;
reviewer judgment should not determine whether it is enforced.

Relevant files:

- `ops/mastra-agents/reviewer/src/mastra/build-phase.ts`
- `scripts/lint-framework.mjs`
- `scripts/framework-lint.test.mjs`
- `.github/workflows/ci.yml`

## 4. Medium: point machine work to the adversarial-review skill

The session initially followed the generic code-review route and produced an over-specified external
review prompt. Todd had to redirect the agent to the machine's actual
`.agents/skills/adversarial-review/SKILL.md` procedure. The new machine Pstack pointer correctly says
that proof follows adversarial review, but the standing instructions do not identify how a machine
adversarial review is performed.

Add one short navigation pointer to `AGENTS.md`: machine changes use the project-local
`adversarial-review` skill, followed by machine Pstack verification. Keep the procedure itself in
the skill rather than duplicating it in always-loaded instructions.

Relevant files:

- `AGENTS.md`
- `.agents/skills/adversarial-review/SKILL.md`
- `docs/agents/machine-pstack-verification.md`

## 5. Medium: expose structured progress for long machine proofs

The implementation session made 1,137 execution calls, including 391 session polls, 59 Git-status
checks, and 253 artifact-related inspections. Much of that activity compensated for silent or hung
long-running commands.

Have the proof launcher maintain one atomic status record containing its phase, candidate identity,
owned PID, last-progress time, terminal result, and artifact paths. Agents could monitor that one
record instead of repeatedly probing processes, Git state, and partial evidence.

## Improvement already completed during the session

The sequencing problem was repaired by `docs/agents/machine-pstack-verification.md`. Machine Pstack
proof now follows implementation and adversarial review, ordinary proof is separated from
verification-skill maintenance, and stale or identity-mismatched proof fails closed. Keep that
change; do not add another copy of the same process to the standing instructions.
