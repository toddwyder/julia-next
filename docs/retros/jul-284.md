# JUL-284 retrospective

Written from the retro that ran inside session `13351dad-0d36-42f1-a43b-6e1d016cfa3e`
(29 October 2026, 16:04–23:39 UTC). That session carried Slice 4 from its sub-issue to Todd's yes,
then carried PR #381 through the reflect follow-ups, so it holds two units of work: the slice
(183 messages, 530 tool calls) and the PR-381 edits after 21:19. Only the slice has been retro'd.

The slice shipped. Both of its code mistakes were caught by Todd or by hand, not by this repo's
checks, which is where each item below aims.

## 1. High: the tracker write could swallow a body and still report success

Todd's JUL-284 merge message (3,745 characters) and the JUL-276 merge comment (1,783 characters)
both landed as the literal text `/tmp/c284.md` and `/tmp/c276.md`. They were found 50 minutes later
by opening the card. `scripts/linear-cli.mjs` took `comment <ID> <body>` only as argv and printed
`{id,url}` on success, so writing the body to a file first — the habit that protected the text —
produced a 12-character write that looked like a 3,745-character one.

The check that catches it: `comment <ID> --file <path>` and `-` for stdin, a refusal when the body
names an existing file, a printed `posted N characters`, and `comments <ID>` to read the card back.
Landed in PR #381, with the refusal and the path guard each shown failing when removed.

## 2. High: the dashboard's build and lint were not in CI

`.github/workflows/ci.yml` ran the dashboard's unit tests through `test-owners --run local` and
never `npm run lint` or `npm run build` in `dashboard/`. The slice's one real build break — a
`readFileSync(new URL('…roles.json'))` that crashed during static generation — was caught because
an agent typed the command. A dashboard build break could merge green.

The check: `dashboard/scripts/dashboard-build.test.mjs`, picked up by the dashboard's own test glob
and run by the existing package-tests job. It fails when either command fails, so a red build now
stops the PR instead of the preview. Landed in PR #381.

## 3. High: the lanes could pass on code that was not the code shipped

`dashboard/scripts/lanes.mjs` spawned `server.js` against whatever `.next` held and always on its
own `127.0.0.1`. That produced both false passes in this slice: the pre-hydration effort bug was
invisible because the lane's page had already hydrated, and a reverted `onePerName` still passed
until a rebuild. It also meant the preview address Todd clicked was never the address any proof
ran against.

The check: refuse to drive a `.next` older than any file under `app/`, `lib/` or `server.js`, and
`--url <address>` to point the same lanes at a handed address. Landed in PR #381.

The runner was also patched nine times by piping `python3` string replacements into it with no
assertion that the replacement matched, which can leave a "fixed" lane passing on old behaviour.
Any scripted edit now has to assert the replacement count.

## 4. Medium: "why 2 of 74 models" needed a throwaway controller boot

`scripts/sweep.mjs` has an injectable `listModels` for tests, but its only production entry point
writes state, so the investigation went through `.tmp-cc.mjs`, a text dump, and a second script. A
`--explain` mode that prints, per provider, how many models came back, which account claims them,
and every model dropped with its reason, answers that in one command. Not built; the mechanism
version of the reflect lesson about rows in versus rows out.

## 5. Medium: the scorecard buys `Cost: unknown` with a 22 GB copy

`scripts/scorecard.mjs` copies the observability store beside the binary before opening it, so on a
box where the store outgrows free disk every card reports `unknown` — JUL-284's scorecard says cost
`unknown` for that reason. Opening the store with `immutable=1` read-only avoids the lock and the
copy. Mitigated, not solved: the cost ledger and `trace-store sweep` now give the scorecard a cost
without a copy, and mining keeps the numbers before payloads are deleted.
