# Lessons from the ten retro sessions, 30 October 2026

Ten sessions ran against four Complete cards — JUL-272, JUL-274, JUL-283 and JUL-208 — and raised 54 findings. This is the same material with repeats merged: 22 distinct mistakes. Each one names the check that would catch it and what that check would block today.

The pyramid order is the point of the ranking. A deterministic check sits highest, a reviewer judgement rule below it, and a written instruction last, because an instruction that already exists and still failed has proved it cannot hold.

## High

1. **A bad proof is accepted because the proof was never of the thing being shipped.** A screenshot of a stale server, a lane run on a local build while the handover address served something else, and a comparison shrunk to fit all passed. Check: name the candidate commit and the exact address in the proof, fetch that address, and reject proof produced elsewhere. Blocks: handing Todd a 404 cookbook page, another build's passing lanes, or evidence too small to read. Derived from JUL-272 (`65bcdc26`), JUL-283 (`7319f915`).

2. **A green check that checks nothing.** `npm run lint` printed "graph/langgraph does not exist yet; passing" and CI ran it, so a UI slice shipped with application lint never executed. Check: make the lint target mandatory and fail when it is absent, and run `npm run lint` and `npm run build` in the dashboard in CI. Blocks: the same badge being reported green over code no linter read. Derived from JUL-272 (`65bcdc26`); the dashboard half is recorded in `docs/retros/jul-284.md`.

3. **Credentials reach the transcript.** Whole settings files, an `apiKey` value, the service-account token and a Firebase `tempLoginState` were printed while investigating a model pack; the vault wrapper only covers commands it launches. Check: redact at the tool-output boundary and test with seeded secrets that none of them appears in stdout, stderr or errors. Blocks: disclosing login state or provider keys during routine diagnostics. Derived from JUL-283 (`c905344b`, `6c81431a`).

4. **The live chat database was edited by hand.** Pack ids were rewritten through raw SQLite while byte lengths were counted as proof, and a later repair touched the same store. Check: a supported transactional command with readback, and a test that decodes fixtures with the installed serializer, changes one field, reopens through the thread API and asserts every other field is unchanged. Blocks: chat records that no longer open. Derived from JUL-283 (`c905344b`, `7319f915`).

5. **Absent telemetry is reported as a successful run.** An empty run store rendered as a priced `$0.00` success, and a reply with no model steps printed as a zero-step run. Check: regression tests seeding an empty store and a step-less reply; both render unknown or incomplete. Blocks: green scorecards for runs whose records do not exist. Derived from JUL-274 (`2a84df76`, `456aaba2`).

6. **A failing check disappears behind a filter, a tail or a lane summary.** A shell chain ending in `tail` returned tail's status, a log filter hid a failure, and lane aggregation reported the last step. Check: one runner that keeps the first nonzero status and prints it alongside the tail; lane summaries that fail when any step failed. Blocks: a failed test, lint or lane step looking green. Derived from JUL-283 (`6c81431a`), JUL-274 (`2a84df76`).

7. **Real state is mutated without knowing whose state it is.** A rules proof could write into the live Firebase project, and a production domain was nearly added to another project's host. Check: require the target project id explicitly before any real mutation, accept project existence only from a success response containing an id, and check deployment identity after every deploy including the changed route. Blocks: a routine local proof becoming a production write. Derived from JUL-208 (`4c6f4323`, `014309f9`).

8. **A property is claimed without asserting it on the artifact the run produced.** The stranger-membership proof never asserted the outsider was absent from the provisioned list, and provisioning was not checked to return a key it had not revoked. Check: assert the claim directly on the produced list and key, with a regression case for mint-before-cleanup ordering. Blocks: a fixture edit that quietly admits the outsider, and a revoked-key ordering bug that still exits 0. Derived from JUL-208 (`4c6f4323`).

9. **The finish line is read as "merged".** Success was declared because the PR was created, while Todd's UAT had not answered; later a run ended with the card still in Backlog. Check: the scorecard judges stops against the recorded UAT yes time, and the reviewer rejects a final report that stops at merge without main CI on the merge commit and a Complete card. Blocks: delivery called done with Todd's question still open. Derived from JUL-274 (`0a4f687b`, `2a84df76`).

10. **A second harness process attaches to the running conversation.** A scratch `mastracode` launch resumed the live thread, hit the store lock and started a duplicate turn. Check: require an explicit new or resumed thread before the first turn and refuse a thread already running. Blocks: duplicate inference and lost observability during a diagnostic. Derived from JUL-283 (`c905344b`).

11. **Context limits guard chat but not the observer.** A chat-only guard passed while observational memory failed with "Input too long", and the proof that followed ran with memory disabled. Check: seed an oversized backlog with memory enabled and require both requests to fit. Blocks: a "protected" chat that still stalls. Derived from JUL-283 (`7319f915`).

## Medium

1. **A test runner answers the first argument and exits 0.** `--plan --install --run` returned the plan and success. Check: surplus arguments exit nonzero with usage. JUL-274 (`0a4f687b`).

2. **Extra credentials are demanded before the existing feature is tried.** Todd was asked to provision client credentials for an inbox ping that Linear's reminder feature already did. Check: use `issueReminder` with the existing key and read the notification back. JUL-274 (`0a4f687b`).

3. **A question's wait is measured to the wrong timestamp.** A 29-minute wait scored zero because the user row is written after the agent resumes. Check: end the wait at the answer timestamp, tested with answer → activity → row ordering. JUL-274 (`0a4f687b`).

4. **An old ping is reused as proof of a later notification.** Check: bound ping evidence to the wait it covers. JUL-274 (`0a4f687b`).

5. **The scorecard truncates the reply it is evidence of.** Check: an end marker after a long multiline reply must survive rendering. JUL-274 (`2a84df76`).

6. **Model provenance is reconstructed instead of read.** Answering model came from repeated SQLite queries and settings defaults. Check: one read-only command returning thread id, time, provider and model, or an explicit unavailable. JUL-274 (`2a84df76`).

7. **The effective model of each chat mode is never compared with the approved roles.** Plan and fast modes still billed Opus. Check: a read-only preflight over build, plan and fast. JUL-274 (`0a4f687b`).

8. **The same 91k-character skill is reinjected all session.** Check: cache loads by path and content digest, returning a receipt for an unchanged second load. JUL-274 (`2a84df76`).

9. **Tool start and completion times are not exported separately.** Check: assert both timestamps in the export. JUL-274 (`0ad81825`).

10. **Lane servers are parked global state.** Check: owned processes with verified teardown, and no killing of a process merely because it holds the port. JUL-283 (`6c81431a`).

11. **A layout gate passes while labels are clipped.** Check: require whole-label visibility, not a successful click. JUL-283 (`6c81431a`).

12. **A streamed screen is asserted before its content arrives.** Check: wait for the cards before checking Back. JUL-283 (`6c81431a`).

13. **The integration test does not use the checked-in configuration.** Check: run the real sweep config. JUL-283 (`6c81431a`).

14. **Pack diagnostics are improvised.** Multi-megabyte source scans and hand-written blob decoding answered a small settings question. Check: a bounded read-only pack reference and diagnostic. JUL-283 (`c905344b`).

15. **Generated text is presented as a captured screen.** Check: reviewer labels SDK-derived output as derived. JUL-283 (`c905344b`).

16. **A repair lives outside the repo and outside the running process.** The retry fix sat in `~/.local/share/mastracode/patches/` and the loaded module was old. Check: versioned installer plus a running-process probe. JUL-283 (`7319f915`).

17. **A whole-store copy runs without checking free space.** The scorecard died with `ENOSPC`. Check: count the store and WAL, keep a margin, and report unavailable instead of copying. JUL-283 (`7319f915`).

18. **A resumed chat is attributed only from a formal kickoff line.** Check: fall back to the opening message's card reference. JUL-283 (`7319f915`).

19. **The tracker cannot move a card.** Merged slices sat in Backlog. Check: a named workflow-state command that validates the state name. JUL-283 (`7319f915`).

20. **The recorder is never run twice when the journey changes.** Check: rerun against retained proof-project state and fail on identity or leftover data. JUL-208 (`4c6f4323`).

21. **Sign-in and save feedback wait on a telemetry call.** Check: keep those responses pending with the reporting endpoint stalled. JUL-208 (`014309f9`).

22. **A lost write is repeated blind.** Check: repeated card comments converge on one acknowledged comment. JUL-208 (`014309f9`).

23. **A model check never runs in CI.** Check: run the recipe model check when its model or covered code changes. JUL-208 (`014309f9`).

24. **A blocker is claimed without evidence or exhausted alternatives.** Check: record operation, principal, exact error, alternatives tried and remaining uncertainty. JUL-208 (`4c6f4323`, `014309f9`).

25. **A proof tool is not exercised in CI, and its install has no deadline.** Check: run launch, Doctor and cleanup in CI with a short browser-install timeout. JUL-272 (`65bcdc26`).

26. **Evidence output is overwritten by the next spec run.** Check: keep every invocation's output. JUL-272 (`65bcdc26`).

## Low

1. **A trace probe is run without reading the records back.** Check: a verifier that finds spans for the exact thread id. JUL-274 (`0ad81825`).

2. **The SDK path is assumed from the package depth.** Check: resolve from the installed executable. JUL-283 (`6c81431a`).

3. **The required-PR check is evaluated on the first branch push.** Check: evaluate after the PR exists, so no empty commit is needed. JUL-272 (`65bcdc26`).

## Where these belong

Twenty of the 54 findings already have their fix in the repo, mostly from the reflect pass recorded in `docs/retros/jul-284.md`; the other 34 are unbuilt. The two that recur in every card are "a green check that checked nothing" and "the proof was not of the artifact being shipped", which is why they head the list: both are detectable mechanically and neither is detectable by asking an agent to be careful.
