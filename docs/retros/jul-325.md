Shipping round, which returned PASS+NOTES. The change adds only

`description: Invalid input: expected string, received undefined`; the agent
retried the same command with a description and it ran. No verdict was affected,
but the rejected call is recorded in the command table. This is the same class
as JUL-322 finding 5 (and the JUL-316 round), so it has now happened at least
three times.

Evidence: `/home/ubuntu/julia-builder/.artifacts/remediation/pr-431/determination-1.md`, command 1.

Check: `execute_command` requires `description` in its input schema and refuses
before running; the Shipping playbook
(`.agents/skills/poteto-mode/playbooks/shipping.md`) does not mention the field,
so the retry recurs.

Status: open.
