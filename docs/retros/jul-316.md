## 1. Medium: a "No card:" line does not clear a card named in the title

The practice pull request had to end up cardless, and getting there took two metadata-only commits.
`e964f49` ("Say on the practice pull request that it names no card") added a `No card:` line to the
body, but the PR still named a card, so `check-branch-pr` kept demanding that card's scorecard.
`a69eace` ("Keep the practice pull request cardless") removed the card reference and that is the
state that stayed. Both commits change no files (`git show` is empty on each), so all three
Shipping rounds reviewed the same one-sentence note.

The reason is in `scripts/check-branch-pr.mjs`: cards are collected from
`${pull.title ?? ''}\n${pull.body ?? ''}` (line 33), and `declaresNoCard` only skips the check when
there are no cards at all (line 35). A body that says "No card: …" beside a title that still
names `JUL-…` does not pass, and the test at line 76 pins that: "a pull request that names a
card still needs that card's scorecard, whatever its body says."

Check: `scorecardGaps` plus `declaresNoCard`, with the test at line 76 and the matching "No card line
with no reason" test at line 69. Status: built.

## 2. Low: the Shipping agent's first shell call in every round omitted the required description

In all three determinations, command #1 is a refused call whose returned text is the tool's
validation error "description: Invalid input: expected string, received undefined"; the agent then
retried the same command with a description and it ran. The traces show the same pair (a call with
no `description`, then the identical call with one). No verdict was affected, because the retry
succeeded each time, but the rejected call is recorded in every determination's command table.

Check: `execute_command` requires `description` in its input schema, so the tool refuses before
running. Status: built (validation); the Shipping playbook does not mention the field, so the retry
recurs.
