# JUL-338 retrospective: a card begins in Mastra Studio, and the build stage is a real agent

JUL-338 shipped as `b4ba0e3` (PR #446) on 5 November 2026, after 56 minutes and 1
Shipping round, which returned PASS. The change makes Mastra Studio's run form the only way a card
starts, turns the build stage into a real agent step that holds the repository as a workspace, and
adds the fingerprinted machine-program list plus the Studio-start check. It touched 27 files.

## 1. High: a pull request body that names another card still reds CI, and the only way back is a close and a reopen

The pull request body named another card beside JUL-338, so `check-branch-pr` demanded a scorecard for
that card too, CI went red on `repository-hygiene`, and the token cannot restart a run. The body was
reworded to name only JUL-338 and the checks were re-run.

Evidence: the commit's own `Re-run the checks after the pull request body stopped naming another
card (JUL-338)` sub-commit; the AGENTS.md rule row "A pull request that names a card carries
that card's scorecard with a measured cost."

Check: `node scripts/check-branch-pr.mjs` ran the published rule against the body and failed it.

Status: built. The check already existed and caught the mistake before merge; no new code was needed.

## 2. Medium: the no-fakes check read the flow's design stand-in as a fake outside service

The build stage is now a real agent step, so the flow's tests drive it with a stand-in model. The
no-fakes check read that as a test replacing an outside service and failed the branch. The exemption
was scoped to `machine/flow/` only, with a test proving it does not widen to any other folder.

Evidence: the commit's `Keep the machine flow's own stand-ins and refuse them everywhere else
(JUL-338)` sub-commit; `scripts/check-no-fakes.mjs` `STANDINS_BY_DESIGN`; the new test in
`scripts/check-no-fakes.test.mjs`.

Check: `scripts/check-no-fakes.mjs` plus its test, which asserts the exemption keeps
`machine/flow/workflow.test.mjs` clean and still refuses a stand-in elsewhere.

Status: built.

## 3. Medium: the old launcher parsed garbled `gh` output and died before reaching Shipping

The launcher that began a card from the command line crashed before reaching Shipping because it
parsed garbled `gh` output. This card's first thread spent its 49 model steps on that fix, and the
launcher was then deleted with its test, so a card can no longer be started outside a run.

Evidence: `docs/advisor-notes/plans/stock-machine-plan-2026-11-03.md` ("The old launcher crashed
before reaching Shipping (it parsed garbled gh output)"); the scorecard's thread
`394fb337` "JUL-338 launcher garble fix and run"; the Shipping determination's criterion 6
(`ls scripts/start-machine*` returned no such file).

Check: `scripts/start-machine.mjs` and `scripts/start-machine.test.mjs` are gone, and
`node scripts/check-agent-links.mjs` passes.

Status: built.

## 4. Medium: two sessions started after the launcher and recorded no trace rows

The scorecard prices the card at $0.23 and reports two sessions that started after the launcher
with no trace rows, so their cost is permanently missing from this card's record. The launcher that
caused them is deleted, so the class cannot recur.

Evidence: `docs/scorecards/JUL-338.md` (`Cost incomplete: 2 sessions of this card started after
the launcher and recorded no trace rows`).

Check: the scorecard reports the gap on its `Cost incomplete:` line rather than estimating it.

Status: built, for the class; the gap stays on this card's record.

## 5. Low: the Studio entry refused to start unless `FLOW_DIR` was absolute

`src/mastra/index.ts` used to throw `Set FLOW_DIR to the absolute path of a run folder` whenever
`FLOW_DIR` was unset or relative, so a first run failed before it began. It now resolves a default
of `.artifacts/flow/studio`, which is what the check and the runbook rely on.

Evidence: the old code in `src/mastra/index.ts` (`if (!dir || !dir.startsWith('/')) { throw ... }`).

Check: `scripts/check-studio-start.mjs` boots Studio with `FLOW_DIR` set to a temp directory and
reads the run form back; `docs/agents/server-runbook.md` documents the default.

Status: built.

## 6. Low: the span stamper assumed every run named a card

`cardStamper` stamped `card` onto every span unconditionally, so a Studio server started without a
card (the new default) would stamp an empty card on every span. The guard returns the span
unchanged when there is no card.

Evidence: `machine/flow/mastra.mjs` (`if (!span || !card) return span;`); `src/mastra/index.ts`
(`card: process.env.FLOW_CARD ?? ''`).

Check: `node --test machine/flow/trace.test.mjs` and `machine/flow/workflow.test.mjs` passed, and
`npm run check:studio` passed.

Status: built.

## What the machine should keep doing

Keep starting every card from Studio's run form and keep the launcher deleted; keep the no-fakes
exemption scoped to `machine/flow/` with its narrowness test; keep the machine-program list
fingerprinted and checked in CI; and keep recording incomplete cost, deleted-launcher sessions and
refused tool calls as notes rather than estimates.
