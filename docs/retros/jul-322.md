# JUL-322 retrospective: the hygiene check passes a pull request whose scorecard states why its cost is short

JUL-322 shipped as `c5dda41` (PR #428) on 3 November 2026, after 14 minutes and one Shipping round, which returned PASS. The change makes `scripts/check-branch-pr.mjs` read each scorecard once and split what it says into failures that stop the pull request and notes it passes with: a `- Cost incomplete:` line becomes a note printed on stdout, while a cost that is unknown, zero or missing still fails exactly as before.

## 1. High: the check refused a pull request whose scorecard honestly said why its cost was short

Before this card, any `- Cost incomplete:` line turned the whole pull request into a failing gap, even when the line named sessions that started after the launcher and recorded no trace rows and therefore had no data to price. That hid the gap instead of measuring it: the pull request that raised this card (JUL-319, PR #425) carried a scorecard with `Cost: **$0.37**` and `Cost incomplete: 4 sessions of this card started after the launcher and recorded no trace rows`, and under the old rule it could not merge.

Evidence: `docs/agents/jul-322/decisions.tsv` row 1 ("A `- Cost incomplete:` line is a note, not a failure"); the pre-change code quoted in determination-1.md command 24 (`if (incomplete) gaps.push(... with a cost that is known to be short: ${incomplete}`); the old wording in `AGENTS.md` and `docs/agents/server-runbook.md` that the check refuses a branch whose scorecard names an incomplete cost.

Check: `scorecardFindings` in `scripts/check-branch-pr.mjs` now returns `{ failures, notes }`, and an incomplete-cost line on a scorecard whose cost is otherwise measured becomes a note; `main()` prints it on stdout before any failure output. Held by `scripts/check-branch-pr.test.mjs` ("a cost the scorecard says is short passes the pull request and is printed as a note", "a real scorecard that says why its cost is short passes and is printed as a note") and the live run in determination-1.md command 23, which printed PR #425's reason and exited 0.

Status: built.

## 2. Medium: a note printed after a failure block is the part a reader scrolls past

The check reads each scorecard once, and both answers have to come from that one read in an order a reader keeps: the passing reason first, then the failures. Printing the note after the failure block (or from a second read) risks losing the stated reason in CI output.

Evidence: `docs/agents/jul-322/decisions.tsv` row 3 ("The check reads each scorecard once and prints the reason on stdout before any failure output").

Check: `scripts/check-branch-pr.mjs` `main()` prints the notes heading and notes, then the branch and scorecard failures; `checkBranchPullRequests` returns `{ branches, scorecards, notes }` from a single `scorecardFindings` call. Held by the test suite (14 tests at the time of the determination).

Status: built.

## 3. Medium: a zero cost or a missing Cost line must still fail even beside an incomplete-cost line

Relaxing the short-cost case must not quietly relax the two costs that still cannot be checked. A scorecard that carries an incomplete-cost line but prices its card at `$0.00` or has no `Cost:` line at all still stops the pull request, and produces no note, because a note saying the pull request passes beside a failing cost would be false.

Evidence: `docs/agents/jul-322/decisions.tsv` row 5 ("A cost that is unknown, zero or missing is not read for an incomplete line"); commit `b24d335` ("Pin the costs that still stop a pull request (JUL-322)").

Check: `scripts/check-branch-pr.test.mjs` ("a cost of zero fails the pull request even with an incomplete-cost line", "a scorecard with no Cost line fails the pull request"), both asserting `failures.length === 1` and `notes` empty.

Status: built.

## Reflection: why the card failed

No Shipping criterion failed on PR #428: the single determination was PASS on `c48b821`. The failure this card exists to fix is the one the check used to produce. Quoted from the pre-change code in determination-1.md command 24:

`const incomplete = /^- Cost incomplete: (.*)$/m.exec(written)?.[1];`
`if (incomplete) gaps.push(`PR #${pull.number} carries ${path} with a cost that is known to be short: ${incomplete}`);`

That line treated an honest reason as a failing gap, so a pull request whose scorecard stated why its cost was short could never merge; on JUL-319 that line named four sessions that started after the launcher and recorded no trace rows, sessions with no data to price, so the cost could never be completed and the branch could never pass. The cause was confusing "a cost with a stated reason" with "a cost that cannot be checked": the incomplete line is evidence about the measurement, not a defect in it. The fix is to keep the two separate — failures stop the pull request, notes pass and are printed — so the stated reason reaches the reader instead of being the thing that hides it.
